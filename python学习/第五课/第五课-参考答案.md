# A 组 · `for` 与 `range`

### A1 · 重复 5 次 【新】

```python
for i in range(5):
    print(i)
```

**实际输出**

```
0
1
2
3
4
```

> **`range(5)` 给 5 个数：0~4。** 不含 5。

---

### A2 · 从 1 到 5 【新】

```python
for i in range(1, 6):
    print(i)
```

**实际输出**

```
1
2
3
4
5
```

> **含头不含尾**：要到 5，就得写 `range(1, 6)`。
> 和切片是同一个规则——`nums[1:4]` 取 1、2、3。

---

### A3 · 步长 【新】

```python
for i in range(1, 10, 2):
    print(i)
```

**实际输出**

```
1
3
5
7
9
```

> 第三个参数是**步长**，和切片一模一样。
> **步长 2 = 隔 1 个取 1 个**（第三课那张换算表照样管用）。

---

### A4 · 遍历列表 【新】

```python
fruits = ["苹果", "香蕉", "橘子"]
for f in fruits:
    print(f)
```

**实际输出**

```
苹果
香蕉
橘子
```

> **`for f in fruits:` = "让 `f` 依次等于列表里的每个元素"**。
> 不用下标，不用 `len()`，**直接给你元素**。
>
> 这是 Python 的 `for` 和 C 的 `for` 最大的区别。

# B 组 · 两种经典模式

### B1 · 累加器 【新】

```python
nums = [10, 20, 30, 40]

total = 0
for n in nums:
    total = total + n

print(total)
```

**实际输出**

```
100
```

**死格式三步：**

| 位置 | 代码 |
|---|---|
| 循环**之前** | `total = 0`（桶清零） |
| 循环**之内** | `total = total + n`（往桶里加） |
| 循环**之后** | `print(total)`（看结果） |

> **`sum(nums)` 也是 100。你现在能自己写出 `sum` 了。**

---

### B2 · 计数器 【新】

```python
nums = [3, 8, 12, 5, 20, 7]

count = 0
for n in nums:
    if n > 10:
        count = count + 1

print(count)
```

**实际输出**

```
2
```

**逐步看：**

| `n` | `n > 10`？ | `count` |
|---|---|---|
| 3 | 否 | 0 |
| 8 | 否 | 0 |
| 12 | **是** | **1** |
| 5 | 否 | 1 |
| 20 | **是** | **2** |
| 7 | 否 | 2 |

> **和累加器一模一样**，只是"加的是 1"而不是"加的是元素"。

---

### B3 · 找最大 【新】

```python
nums = [3, 8, 12, 5, 20, 7]

biggest = nums[0]
for n in nums:
    if n > biggest:
        biggest = n

print(biggest)
```

**实际输出**

```
20
```

**"打擂法"**：先假定第一个是擂主，然后每个元素上来挑战，赢了就换擂主。

| `n` | `biggest` 变化 |
|---|---|
| 3（初始） | 3 |
| 3 | 3（不大于） |
| 8 | **8** |
| 12 | **12** |
| 5 | 12 |
| 20 | **20** |
| 7 | 20 |

> **这就是 `max()` 的内部做法。**

# C 组 · `for` + `if`

### C1 · 筛选 【新】

```python
for i in range(1, 11):
    if i % 2 == 0:
        print(i)
```

**实际输出**

```
2
4
6
8
10
```

> **`if` 在循环里面 → 每轮判断一次。**

---

### C2 · 查找 【新】

```python
fruits = ["苹果", "香蕉", "橘子"]
for f in fruits:
    if f == "香蕉":
        print("找到了")
```

**实际输出**

```
找到了
```

---

### C3 · 统计字符 【新】

```python
s = "hello world"

count = 0
for ch in s:
    if ch == "l":
        count = count + 1

print(count)
```

**实际输出**

```
3
```

> **`for ch in s:` 遍历字符串的每一个字符**（包括空格）。
> `"hello world"` 里的 `l` 出现在 h-e-**l**-**l**-o 和 wor-**l**-d，共 **3** 个。
>
> **这是"统计字符"类题目的固定套路。**

# D 组 · `while`

### D1 · `while` 基本 【新】

```python
i = 1
while i <= 5:
    print(i)
    i = i + 1
```

**实际输出**

```
1
2
3
4
5
```

**死循环演示**（把 `i = i + 1` 注释掉之后）：

```
1
1
1
1
1
...（永远不停）
```

**用 `Ctrl + C` 停掉。**

> **防止死循环的口诀**：
> **写 `while` 时，先写"改条件变量"那一行，再回头写中间的代码。**
> 这样不可能忘。

---

### D2 · 不知道要几次 【新】

```python
thickness = 0.1
count = 0

while thickness < 1000:
    thickness = thickness * 2
    count = count + 1

print(count)
```

**实际输出**

```
14
```

**为什么是 14 次：**

| 折的次数 | 厚度 |
|---|---|
| 0 | 0.1 |
| 1 | 0.2 |
| … | … |
| 13 | 819.2 |
| **14** | **1638.4** ✅ 超过 1000 |

> **`while` 的场合就是"次数未知"**——你不知道要折几次，只能一直折到条件满足。
>
> **对比复习一 甲3**：那次问"折 10 次后多厚"（**次数已知** → 用 `2 ** 10`）；
> 这次问"折几次才够"（**次数未知** → 用 `while`）。
> **同一个场景，两种问法，两种工具。**

# E 组 · `break` / `continue`

### E1 · `break` 【新】

```python
for i in range(1, 11):
    if i == 5:
        break
    print(i)
```

**实际输出**

```
1
2
3
4
```

> **注意 `print(i)` 写在 `break` 后面**——所以 5 不会被打印，循环在 5 处直接结束。

---

### E2 · `continue` 【新】

```python
for i in range(1, 6):
    if i == 3:
        continue
    print(i)
```

**实际输出**

```
1
2
4
5
```

> **`continue` 只跳过 3 那一轮，循环继续。**
> 所以 4、5 照常打印——**这是它和 `break` 的关键区别。**

# F 组 · 两道特殊题

## F1 · 读官方文档自学 【新】★ 规则七

### 五个问题的答案

**Q1：`print(range(5))` 实际输出什么？**

```python
print(range(5))
```

**实际输出**

```
range(0, 5)
```

**不是 `[0, 1, 2, 3, 4]`！**

**Q2：`type(range(5))` 是什么？**

```python
print(type(range(5)))
```

**实际输出**

```
<class 'range'>
```

**它是一种独立类型，不是列表。**

**Q3：`range` 对象和列表最大的区别是什么？**

> **`range` 对象不会真的把所有数字生成出来、存起来。**
> **它只在被迭代时，一个一个地"算"出来给你。**
>
> 文档原话：
>
> > "该对象只有在被迭代时才一个一个地返回所期望的列表项，
> > **并没有真正生成过一个含有全部项的列表，从而节省了空间。**"

**Q4：为什么要这么设计？**

> **为了省内存。**
>
> `range(100000000)` 如果真生成一个含 1 亿个整数的列表，要占几百 MB 内存；
> 但 `range` 对象**只存三个数**（start、stop、step），**几乎不占空间**，
> 用到第几个就算第几个。
>
> **这叫"惰性求值"**——需要的时候才算，不提前造。

**Q5：想变成真正的列表怎么写？**

```python
print(list(range(5)))
```

**实际输出**

```
[0, 1, 2, 3, 4]
```

**用 `list()` 包一下。**

### 完整验证

```python
print(range(5))
print(type(range(5)))
print(list(range(5)))
print(range(0, 10, 3))
print(list(range(0, 10, 3)))
```

**实际输出**

```
range(0, 5)
<class 'range'>
[0, 1, 2, 3, 4]
range(0, 10, 3)
[0, 3, 6, 9]
```

### 这题的意义

> **你每天都在用 `range`，但可能以为它返回的是列表。**
> **不是。** 它返回一个"会算数的对象"。
>
> **这类"看起来像但其实不是"的东西，Python 里还有很多。**
> **读文档就是发现它们的方式。**

## F2 · 改错题 【新】★ 规则八

### 问题在哪

```python
total = 0
for n in nums:
    total = n        # ❌ 这是"替换"，不是"累加"
```

**`total = n` 的意思是"把 `n` 的值**覆盖**到 `total` 上"**——原来 `total` 里存的什么都不管了。

**跑一遍看：**

| 轮次 | `n` | 执行 `total = n` 后 |
|---|---|---|
| 1 | 10 | `total = 10` |
| 2 | 20 | `total = 20`（**10 被覆盖了**） |
| 3 | 30 | `total = 30`（**20 被覆盖了**） |

**所以最后 `total` 等于 `30`——也就是列表的最后一个元素。**

**它算出来的不是"总和"，是"最后一个数"。**

### 改对

```python
total = 0
nums = [10, 20, 30]

for n in nums:
    total = total + n      # ✅ 累加

print(total)
```

**实际输出**

```
60
```

### 为什么一行之差，结果完全不同

| 写法 | 含义 | 效果 |
|---|---|---|
| `total = n` | **替换**：把 `total` 变成 `n` | 只剩最后一个 |
| `total = total + n` | **累加**：在 `total` 原值上加 `n` | 全都加起来 |

> **口诀**：**右边出现 `total` 自己，才是累加。**
>
> ```
> total = n              ← 右边没有 total → 替换 ❌
> total = total + n      ← 右边有 total   → 累加 ✅
> ```
>
> **这个"右边有没有自己"的判断法，能一眼看出是累加还是替换。**

### 这题真正的教训

> **这题不报错**——`total = n` 语法完全正确，程序跑得好好的。
> **它只是悄悄给出了错误的答案。**
>
> **和第四课 E2（`elif` 顺序错）是同一类问题**：**不报错的错误最难发现。**
> 而这类错误的防线只有一条：**拿几个数据自己代进去算一遍。**
