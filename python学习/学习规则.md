### 规则一：习题必须由出题者自己检查

> **每一道题的参考答案，我必须先自己跑通、把真实输出贴进【自检】里。**
> 不允许出现"看起来应该输出 X"这种没验证过的自检。

### 规则二：习题必须贴合课程

> **不超纲，但也不弱。**
>
> - **不超纲**：解题只允许用本课及之前课学过的东西，不许偷偷要求没教的语法。
> - **不弱**：不能是"把例子抄一遍"这种无效练习。
> - **贴合**：每个知识点后面都要有对得上的习题。

### 规则三：不重复（去重义务）

> **同一个知识点只考一次。已考过的，无论隔多久，不再出题。**
>
> - 判断单位是**知识点**，不是题型。换个数字、换个变量名、换个说法的重复，**仍然算重复**。
> - 出题前我必须先过一遍"已考知识点清单"，确认这题有新东西。
> - **如果一道题没有引入任何新知识点，它就不该存在。**

### 规则四：以"留痕"为准，不以"错误"为准

> **文件里存在一个错误，不代表我没掌握。**
> 我可能是有意保留它作为学习痕迹（工作留痕习惯）。
>
> 判断我"会不会"的依据，**只能是**：
>
> | 我注释里的信号 | 我该怎么讲 |
> |---|---|
> | `？`、`不知道`、`为什么`、`我认为这可能错` | ✅ **这个点讲细、多举例、优先回答** |
> | `我知道`、`我故意留的`、`后面我改了`、老版本注释 | **这个点讲一遍就够，不用铺开** |
> | 没写清楚 | ⚠️ **先问我，不要默认我不会** |
>
> **我注释里的问号，就是最准确的缺口清单。** 请直接读它们。
>
> **注意**：这个判断只用来决定**"讲多细"**，
> **不用来决定"考不考"**——按规则三，每个知识点本来就只考一次，**全都要覆盖**。

### 规则五：跳题要给理由

> 我可以跳过任何一题，但**必须写一句"我会，因为 X"**。
>
> - 写对了 → 跳过，不浪费双方时间
> - 写错了 → 立刻暴露缺口，比做十道题都有用
>
> 这比"必须先跑一遍"更好：判断权在我，校验权在你。

#### 规则六：必须有一段"没有答案"的经历

> **第 1 段学完后，插入一个「小项目」。它不是习题。**
>
> - **题目由你（学生）自己提** —— 一个你**真正想要**的东西，哪怕很小
> - **没有参考答案，没有【自检】**
> - 验收标准只有一个：**它对你自己能用**
> - AI 的角色从"出题 + 批改"变成"**代码审查（review）**"——**只提问题，不给答案**
>
> **为什么**：练习题全都有标准答案。而真实开发里，最难的部分恰恰是
> **"没人告诉你对不对"**——你得自己判断。

#### 规则七：从第四课起，知识点不再全由 AI 讲

> **每课至少有一个知识点，AI 不直接讲。** 改成给你：
>
> - **官方文档的具体位置**（`docs.python.org` 的链接和章节）
> - **几个必须回答的问题**
>
> 你自己读、自己试、回来汇报。AI 再补漏、纠错。
>
> **约束**：这个知识点**仍然在本课范围内**（不违反"不超纲"），
> 只是**换了教法**——从"我讲"变成"你读"。
>
> **为什么**：你对 Python 的全部认识目前都来自 AI，**而 AI 会错**（`//` 那次就是）。
> 真正掌握的标志是：**没有老师也不卡住。**

#### 规则八：每课加一道"改错题"

> **给你一段能跑、但结果不对的代码**，让你找出来改对。
>
> - **和"从空白写"完全不同** —— 这是**调试训练**
> - **不给完整答案**，只给"正确输出应该是什么"
> - 真实开发里 **80% 的时间在修别人的代码**，不是从零写
>
> **对手册规则一的补充**：改错题必须验证**两头**——
>
> 1. 坏代码**确实能跑**，而且**输出确实是错的**
> 2. 修好之后，输出**确实是对的**
>
> 只验证第 2 条是不够的：那样可能出一道"根本不用改"的题。

## 二、从你的话里提炼的教学原则

这几条不是规则，是**我理解到的你的需求**，用来指导我怎么写课：

| 你的原话 | 我的理解 |
|---|---|
| "代码的学习必须靠敲" | 理论讲完必须马上动手，不能只读 |
| "用不好的题来骗自己，是绝对吃不到好的" | 无效练习比不练更糟，题必须有真实难度 |
| "我不怕练，我是怕'不会'" | 题量不是问题，超纲才是问题 |
| "第一课做得很好，每个例子都有习题" | 讲完一个点立刻配题，模式是对的 |
| "时间长了可能忘了指令名" | 需要一份可回查的速查文档 |
| **"简单不是不能有，主要是重复性"** | **重复才是无效练习的主因，难度不是** |
| **"重复可以，但除非我真的是'完全不知道'"** | 在真缺口上重复才有意义 |
| **"我意识到了后改"，不是"没掌握"** | 见规则四 |
| **"计算机语言在我眼里是不同的东西，我该重新学"** | **不许用 C# 类比压缩路线或跳知识点** |
| **"超纲等于提前弄，提前弄会降低知识度"** | **不超纲优先级最高——宁可不考，也不提前** |
| **"过度的重复有时候会令人疲惫"** | 每个知识点只考一次 |

**结论（已修正）：**

> ~~宁多勿难~~ → **宁准勿多。**
>
> **每点一题。** 知识点**全部覆盖**，但每个**只考一次**。
>
> 一道重复题的伤害不是浪费时间——**是它会诱发敷衍**。比如硬编码一个答案交差。
> **那比不做更糟：它把"没练"伪装成"练了"，还让人以为问题出在学生身上。**
>
> 第二课的 B2 / B3 / B5 就是这个错：**重复的题 → 无聊 → 敷衍 → 被我误判成"态度问题"。**
> 责任在设计，不在做题的人。

## 三、我的执行承诺与出题策略

### 3.1 执行承诺

由上面的规则推导出的具体做法：

1. **每道题的参考答案我都会实际运行**，把真实输出写进【自检】。
2. **知识点全部覆盖，不跳、不压缩。** 宁可多花时间，不抽地基。
3. **每个知识点只出一题**，出题前必查"已考知识点清单"（见 3.3）。
4. **每题标注**它考的是"新知识"还是"复习旧知识"。
5. **难题给提示**，提示放在可折叠区域，先让你自己想。
6. **答案单独成文**（`第X课-参考答案.md`），先做题再看答案。
7. **绝不超纲。** 只用本课及之前课学过的语法。要教新东西我会先教。
8. **课与课之间不跳步**，但同一课内可以跳题（按规则五，给理由即可）。
9. **改错题验证两头**：坏代码确实能跑且输出是错的，修好后输出是对的（规则八）。
10. **第四课起，每课至少一个知识点由你读官方文档自学**（规则七）。
11. **第 1 段结束后，安排一个"没有答案"的小项目**（规则六）。
12. **每课加"读代码"**：从第四课起，每课至少一题是"给一段代码，说出它在做什么、为什么"（见 3.5）。
13. **维护根目录 `语法速查.md`**：每课结束追加新语法；**你犯过的错追加到第三节「我的易错点」**。
14. **复习课严格按规则九执行**，每三课一次。

> **生效时间**：
>
> | 规则 | 从哪开始 |
> |---|---|
> | 规则六（小项目） | **第 1 段学完后** |
> | 规则七（读文档） | **第四课起** |
> | 规则八（改错题） | **第四课起** |
>
> **第三课不变**（已出题并推送，保持原样，不中途改动）。

### 3.2 出题策略

> 甚至先做一张「Python ↔ C# 对照表」代替基础课。

> **你否了。而且你的理由比我的提案硬：**
>

> >

> 知识要在**新语言里重新长一遍**，删掉中间步骤 = 抽掉地基。
>
> **这一条不许再提。**

**所以策略只有四条：**

#### ① 知识点：全部覆盖，一个不跳

不压缩、不跳过、不搞"这个你会了所以略过"。**每个知识点都要走到。**

看到你会写三级继承、会模式匹配、会用 `$"{x:F2}"`——**那也只是说明你学 Python 会快一些，不代表可以少学。**

#### ② 每个知识点：只考一次

这是对第二课**唯一有效**的修正。

> **不重复 ≠ 可以跳过。**
> **覆盖：全部。出题：每点一次。**

#### ③ 出题要灵活：不要"一个点配一道题"

第二课的毛病是机械对应：讲一个点 → 配一道题 → 下一个点 → 再配一道题。
结果是 20 道互不相干的小题，还互相重复。

**改法：题目要串联前面学过的东西。**

- 一道题可以**同时用到本课新知识 + 前几课旧知识**
- 后面的课要**主动回头用前面课的内容**，让旧知识保持活性
- **综合题不是超纲，是复习**

| | 做法 |
|---|---|
| ❌ 旧 | 讲切片 → 连出 3 道纯切片题 |
| ✅ 新 | 讲切片 → **1 道纯切片题**（练新）+ **1 道"用 f-string 输出切片结果"**（复习第二课） |

#### ④ 严格不超纲（优先级最高）

**只用本课和之前课学过的东西。**

> **超纲等于提前弄，提前弄会降低知识度。**
>
> **宁可不考，也不提前。**

你 C# 里碰过的东西，我讲一遍就够；你没接触过的，我讲细。
判断依据：你 `2025 11 14 03 50` 那个 Unity 项目里的 23 个脚本。

**2. 解释"Python 为什么这么做"**

对比不是捷径，是**理解工具**。
比如 `$"{x:F2}"` ↔ `f"{x:.2f}"` —— 知道对应关系能帮你**记住格式符**，
但**不等于可以少练一遍**。

### 必须重点学的（真正 Python 独有的）

| 概念 | 为什么 |
|---|---|
| **切片** | C# 没有等价物 |
| **负索引** | C# 没有 |
| list / dict / tuple / set 的**字面量语法** | C# 是 `new List<int>{...}` |
| 推导式 | 概念像 LINQ，语法全新 |
| `*args` / `**kwargs` | 概念有，语义不同 |
| 迭代器 / 生成器 | C# 有 `yield return`，概念可迁移 |
| `with` | 类似 `using` |
| `if __name__ == "__main__"` | C# 没有 |
| 装饰器 | 和 `[Attribute]` **机制完全不同** |
| **动态类型的实践含义** | 静态类型养成的直觉会失灵 |
| GIL、多线程不加速 CPU 密集任务 | 对 AI 很重要 |
