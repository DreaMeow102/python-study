## 一、你定的规则

### 规则一：习题必须由出题者自己检查

> **每一道题的参考答案，我必须先自己跑通、把真实输出贴进【自检】里。**
> 不允许出现"看起来应该输出 X"这种没验证过的自检。

### 规则二：习题必须贴合课程

> **不超纲，但也不弱。**
>
> - **不超纲**：解题只允许用本课及之前课学过的东西，不许偷偷要求没教的语法。
> - **不弱**：不能是"把例子抄一遍"这种无效练习。
> - **贴合**：每个知识点后面都要有对得上的习题。

### 规则三：不重复（去重义务）

> **同一个知识点只考一次。已考过的，无论隔多久，不再出题。**
>
> - 判断单位是**知识点**，不是题型。换个数字、换个变量名、换个说法的重复，**仍然算重复**。
> - 出题前我必须先过一遍"已考知识点清单"，确认这题有新东西。
> - **如果一道题没有引入任何新知识点，它就不该存在。**

### 规则四：以"留痕"为准，不以"错误"为准

> **文件里存在一个错误，不代表我没掌握。**
> 我可能是有意保留它作为学习痕迹（工作留痕习惯）。
>
> 判断我"会不会"的依据，**只能是**：
>
> | 我注释里的信号 | 判定 |
> |---|---|
> | `？`、`不知道`、`为什么`、`我认为这可能错` | ✅ **这是真缺口，优先讲** |
> | `我知道`、`我故意留的`、`后面我改了`、老版本注释 | ❌ **已掌握，不要再考** |
> | 没写清楚 | ⚠️ **先问我，不要默认我不会** |
>
> **我注释里的问号，就是最准确的缺口清单。** 请直接读它们。

### 规则五：跳题要给理由

> 我可以跳过任何一题，但**必须写一句"我会，因为 X"**。
>
> - 写对了 → 跳过，不浪费双方时间
> - 写错了 → 立刻暴露缺口，比做十道题都有用
>
> 这比"必须先跑一遍"更好：判断权在我，校验权在你。

## 二、从你的话里提炼的教学原则

这几条不是规则，是**我理解到的你的需求**，用来指导我怎么写课：

| 你的原话 | 我的理解 |
|---|---|
| "代码的学习必须靠敲" | 理论讲完必须马上动手，不能只读 |
| "用不好的题来骗自己，是绝对吃不到好的" | 无效练习比不练更糟，题必须有真实难度 |
| "我不怕练，我是怕'不会'" | 题量不是问题，超纲才是问题 |
| "第一课做得很好，每个例子都有习题" | 讲完一个点立刻配题，模式是对的 |
| "时间长了可能忘了指令名" | 需要一份可回查的速查文档 |
| **"简单不是不能有，主要是重复性"** | **重复才是无效练习的主因，难度不是** |
| **"重复可以，但除非我真的是'完全不知道'"** | 在真缺口上重复才有意义 |
| **"我意识到了后改"，不是"没掌握"** | 见规则四 |

**结论（已修正）：**

> ~~宁多勿难~~ → **宁准勿多。**
>
> **一题一新。** 题量的价值不在"练了多少遍"，而在"碰到了多少个第一次"。
>
> 一道重复题的伤害不是浪费时间——**是它会诱发敷衍**。比如硬编码一个答案交差。
> **那比不做更糟：它把"没练"伪装成"练了"，还让人以为问题出在学生身上。**
>
> 第二课的 B2 / B3 / B5 就是这个错：**重复的题 → 无聊 → 敷衍 → 被我误判成"态度问题"。**
> 责任在设计，不在做题的人。

## 三、我的执行承诺与出题策略

### 3.1 执行承诺

由上面的规则推导出的具体做法：

1. **每道题的参考答案我都会实际运行**，把真实输出写进【自检】。
2. **每道题必须标注"它引入了什么新知识点"**。标不出来的题，删掉。
3. **难题给提示**，提示放在可折叠区域，先让你自己想。
4. **答案单独成文**（`第X课-参考答案.md`），先做题再看答案。
5. **不在习题里使用未教过的语法**。如果某题必须要用新东西，我会先教。
6. **维护"已考知识点清单"**，出新题前必须先过一遍（见 3.3）。
7. **课与课之间不跳步**，但**同一课内可以跳题**（按规则五，给理由即可）。

### 3.2 三类知识，三种处理方式

**这是出题策略的核心。** 你有 Unity/C# 的实际经验，很多"Python 知识"对你其实是**换写法**，不是**学新东西**。

| 类型 | 判断标准 | 举例 | 处理方式 |
|---|---|---|---|
| **A 类** | C# 有，**概念完全相同** | 循环、条件、函数、类、继承、多态、`yield`、`using`≈`with` | **不出题。** 给一张对照表，5 分钟过 |
| **B 类** | C# 有，**写法不同** | `$"{x:F2}"` ↔ `f"{x:.2f}"`；`List<T>` ↔ `[]` | **出 1 题**，只练写法转换 |
| **C 类** | **C# 完全没有** | 切片、推导式、`*args` / `**kwargs`、动态类型的实践含义 | **重点出题**，每题动手 |

> **已确认的 A 类（不要再出题）**：
> 类、继承（你写过三级继承层次）、`virtual`/`override`、`base` 调用、访问修饰符、属性、
> 表达式体成员、组合模式、状态机、循环、条件、函数与参数、`yield`（C# 也有）、
> `using`（≈ `with`）、三元运算符、插值字符串。
>
> **判断依据**：你 `2025 11 14 03 50` 那个 Unity 项目里的 23 个脚本。

**一句话**：**能用 C# 类比出来的，就不出题；出题只出"Python 才有的东西"。**

### 3.4 验收方式也要分类型

| 题目类型 | 验收方式 |
|---|---|

## 六、可以跳过 / 必须重点学

**背景**：你有 C# 实践，所以**不是"编程零基础"，是"Python 零基础"**。

### 可以快速跳过的（C# 已覆盖）

变量、基本类型、运算符、`if`/`while`/`for`、函数定义与调用、返回值、类与继承、异常的概念。

—— 这些你只需要记 Python 的**写法**，不用重新理解概念。

### 必须重点学的（C# 给不了）

| 概念 | 为什么 |
|---|---|
| 缩进即语法 | C# 用 `{}`，Python 用缩进 |
| list / dict / tuple / set | 内置的，不是库。用得最多的四个 |
| 切片 `a[1:5:2]` | Python 的标志性能力 |
| 推导式 | 不会它就写不出 Python 味 |
| 多返回值与解包 | 你课上已经见过 `return a+b, a-b` |
| `for x in 对象` | 直接迭代元素，不是索引循环 |
| 默认参数的坑 | 你课上的 `def twoNumAdd(a=2, b=1)` |
| 迭代器 / 生成器 / `yield` | 数据管道的基础 |
| `with` / 装饰器 / `*args` `**kwargs` | 读懂别人代码的门槛 |
| 模块 / 包 / `if __name__ == "__main__"` | C# 没有对应物 |
| GIL、多线程不加速 CPU 密集任务 | 对 AI 很重要 |
